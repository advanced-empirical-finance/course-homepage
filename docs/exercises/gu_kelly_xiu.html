Empirical Asset Pricing via Machine Learning

This exercise guides you through an actual academic application of machine learning in asset pricing: the core of Empirical Asset Pricing via Machine Learning by Shihao Gu, Bryan Kelly, and Dacheng Xiu (Review of Financial Studies, 2020). The paper runs a horse race of off-the-shelf machine learning methods that predict monthly stock returns from a large set of stock characteristics and macroeconomic variables. Its Internet Appendix, which you find on the paper’s page, describes the implementation details.

Exercises:

  1. Read Section 2 of the paper (“An empirical study of U.S. equities”). The authors approximate the conditional expected return \(E_t\left(r_{i, t+1}\right) = g^\star(z_{i,t})\) with different machine learning methods. The returns are monthly total equity returns from CRSP for all firms listed on NYSE, AMEX, and NASDAQ, starting in March 1957. Use crsp_monthly.parquet from Absalon for the returns.
  2. The paper’s main input is a collection of 94 stock characteristics (Table A.6 in the Internet Appendix). You do not have to compute them yourself: download them from Dacheng Xiu’s homepage and read the readme file.
  3. Rank all characteristics cross-sectionally, month by month, and map the ranks into the \([-1, 1]\) interval (footnote 29). Replace missing characteristics with the cross-sectional median of the month (footnote 30).
  4. Merge the characteristics with the excess returns from CRSP and with the eight macroeconomic predictors of the paper, following Welch and Goyal (2008): dp, ep, bm, ntis, tbl, tms, dfy, and svar. You find them in macro_predictors.parquet in the data-r / data-python folder of the course repository. Make sure the timing is right: the predictors in row \(t\) must be known before the return in row \(t\) is realized.
  5. Build the paper’s 920 covariates: the 94 characteristics, their interactions with the eight macroeconomic predictors, and 74 industry dummies from the first two digits of the SIC code (sic2). The resulting dataset is huge. How can you keep it manageable on your own computer?
  6. Split the sample the way the paper does: 18 years of training data (1957–1974), 12 years of validation data (1975–1986), and the remaining years for out-of-sample testing, with an expanding training sample and a rolling validation sample, refitted once a year. Illustrate the scheme in a figure.
  7. Fit a random forest with 300 trees for the first out-of-sample year (1987). Tune the number of variables considered at each split and the size of the trees on the validation sample. Then set up an elastic net with mixing parameter 0.5 in the same way.
  8. Predict the out-of-sample returns, sort stocks into value-weighted decile portfolios every month based on the predictions, and add a long-short portfolio that buys decile 10 and sells decile 1. Report the average predicted and realized returns, their standard deviation, and the Sharpe ratio of each portfolio.

Solutions:

WarningMind the size of the data

The full dataset has about three million stock-months with 920 covariates, about 20 GB in memory as numbers. The solution therefore stores the covariates year by year and only reads the years a step needs. Fitting the random forest for a single out-of-sample year still takes hours on a laptop. Try every step first on a subsample, for instance a random 10% of the stocks and a smaller tuning grid, before you run it on everything.

Stock characteristics

We build a large collection of stock-level predictive characteristics based on the cross-section of stock returns literature. These include 94 characteristics (61 of which are updated annually, 13 are updated quarterly, and 20 are updated monthly). In addition, we include 74 industry dummies corresponding to the first two digits of Standard Industrial Classification (SIC) codes. (p. 2248)

The authors provide the characteristics on Dacheng Xiu’s homepage; the published paper ends in December 2016, but the file runs until 2021. It is a zipped .csv file of about 1.5 GB, so the download takes a while: we allow it 20 minutes (1,200 seconds). Many characteristics are missing in the first years of the sample, so the column types must not be guessed from the first rows of the file. In R, we read every column as a number; in Python, polars scans the whole file before it decides on the types. The column DATE stores dates as numbers such as 19570329, which we turn into the first day of the month, the convention of the course data.

Scaling and missing values

We cross-sectionally rank all stock characteristics period-by-period and map these ranks into the [-1,1] interval following Kelly, Pruitt, and Su (2019) and Freyberger, Neuhierl, and Weber (2020). (footnote 29)

In every month, the stock with the lowest value of a characteristic gets \(-1\), the one with the highest value gets \(1\), and the others lie in between according to their rank. Missing values keep a missing rank, so they do not distort the ranking of the others. If a characteristic has fewer than two values in a month, there is nothing to rank and the result is missing. Random forests do not care about the scaling of the predictors, but the elastic net and neural networks do.

  • R
  • Python
rank_transform <- function(x) {
  n <- sum(!is.na(x))
  if (n < 2) {
    return(rep(NA_real_, length(x)))
  }
  (rank(x, na.last = "keep") - 1) / (n - 1) * 2 - 1
}

characteristics <- characteristics |>
  group_by(date) |>
  mutate(across(starts_with("characteristic_"), rank_transform)) |>
  ungroup()
def rank_transform(x):
    n = x.count()
    return pl.when(n >= 2).then((x.rank() - 1) / (n - 1) * 2 - 1)


char_cols = [col for col in characteristics.columns if col.startswith("characteristic_")]

characteristics = characteristics.with_columns(
    rank_transform(pl.col(char_cols)).over("date")
)

Another issue is missing characteristics, which we replace with the cross-sectional median at each month for each stock, respectively. (footnote 30)

One of the coauthors, however, writes in a Q&A file that missing values are set to zero. The two statements fit together: in some months, a few characteristics (for instance absacc) have no values at all, so their cross-sectional median is undefined. We therefore first replace missing values with the median of the month and then set what is still missing to zero. After the rank transformation, zero is the middle of the range.

  • R
  • Python
characteristics <- characteristics |>
  group_by(date) |>
  mutate(across(
    starts_with("characteristic_"),
    \(x) replace_na(x, median(x, na.rm = TRUE))
  )) |>
  ungroup() |>
  mutate(across(starts_with("characteristic_"), \(x) replace_na(x, 0)))
characteristics = (characteristics
    .with_columns(
        pl.col(char_cols).fill_null(pl.col(char_cols).median().over("date"))
    )
    .with_columns(pl.col(char_cols).fill_null(0))
)

Returns and macroeconomic predictors

We also construct eight macroeconomic predictors following the variable definitions detailed in Welch and Goyal (2008), including dividend-price ratio (dp), earnings-price ratio (ep), book-to-market ratio (bm), net equity expansion (ntis), Treasury-bill rate (tbl), term spread (tms), default spread (dfy), and stock variance (svar). (p. 2248)

The characteristics are already aligned with the returns they predict: the readme says that for DATE=19570329 you can use the monthly return of March 1957 as the response. The excess returns ret_excess from CRSP therefore merge on the same month. The macroeconomic predictors of a month are only known at its end, so we lag them by one month: the values of February predict the returns of March. We keep mktcap_lag for the value-weighted portfolios at the end. Note that crsp_monthly.parquet starts in 1960, three years after the paper’s sample, which may explain some differences to the paper’s results.

The 920 covariates

We include 74 industry dummies corresponding to the first two digits of Standard Industrial Classification (SIC) codes. […] [The stock-level covariates also include] interactions between stock-level characteristics and macroeconomic state variables. The total number of covariates is 94×(8+1)+74=920. (p. 2249)

In the paper’s notation, the covariates are \(z_{i,t} = (1, x_t')' \otimes c_{i,t}\), where \(c_{i,t}\) holds the 94 characteristics and \(x_t\) the eight macroeconomic predictors. The product with the constant is the characteristic itself, so the covariates are the 94 characteristics, their \(94 \times 8 = 752\) interactions with the macroeconomic predictors, and the 74 industry dummies: \(94 + 752 + 74 = 920\). The macroeconomic predictors themselves are not covariates.

We first describe these steps once and then apply them to each year of data separately: all years together would not fit into the memory of most computers. In R, a recipe lists the steps: step_interact() adds the interactions, step_rm() drops the macroeconomic predictors, and step_dummy() turns sic2 into one column per industry. prep() only needs a few rows to learn the column names, because sic2 is a factor that knows all industries. In Python, we write the same steps as a list of polars expressions, one per new column; polars evaluates them only when we apply them to the data.

  • R
  • Python
characteristics <- read_parquet("data-r/stock_characteristics_monthly.parquet") |>
  mutate(sic2 = factor(sic2))

rec <- recipe(ret_excess ~ ., data = characteristics |> slice_head(n = 1000)) |>
  update_role(permno, date, mktcap_lag, new_role = "id") |>
  step_interact(terms = ~ contains("characteristic"):contains("macro")) |>
  step_rm(starts_with("macro_")) |>
  step_dummy(sic2, one_hot = TRUE) |>
  prep()
characteristics = (pl.read_parquet("data-python/stock_characteristics_monthly.parquet")
    .with_columns(pl.col("sic2").cast(pl.Int64).cast(pl.String))
)

char_cols = [col for col in characteristics.columns if col.startswith("characteristic_")]
macro_cols = [col for col in characteristics.columns if col.startswith("macro_")]
industries = characteristics["sic2"].unique().sort().to_list()

covariates = (
    [(pl.col(c) * pl.col(m)).alias(f"{c}_x_{m}") for c in char_cols for m in macro_cols]
    + [(pl.col("sic2") == s).cast(pl.Int8).alias(f"sic2_{s}") for s in industries]
)

Each file holds the identifiers permno, date and mktcap_lag, the excess return ret_excess, and the 920 covariates. A small helper reads the files of a range of years and skips years without data (crsp_monthly.parquet starts in 1960):

read_years <- function(start, end) {
  files <- paste0("data-r/characteristics_prepared/", start:end, ".parquet")
  files[file.exists(files)] |>
    map(read_parquet) |>
    list_rbind()
}
def read_years(start, end):
    files = [Path(f"data-python/characteristics_prepared/{y}.parquet") for y in range(start, end + 1)]
    return pl.concat([pl.read_parquet(f) for f in files if f.exists()])

Sample splitting

We divide the 60 years of data into 18 years of training sample (1957–1974), 12 years of validation sample (1975–1986), and the remaining 30 years (1987–2016) for out-of-sample testing. Because machine learning algorithms are computationally intensive, we avoid recursively refitting models each month. Instead, we refit once every year as most of our signals are updated once per year. Each time we refit, we increase the training sample by 1 year. We maintain the same size of the validation sample, but roll it forward to include the most recent 12 months. (p. 2250)

For every out-of-sample year, the validation sample covers the 12 years before it, and the training sample everything from 1957 until the validation sample begins. We extend the out-of-sample period until the last year of data.

The paper deliberately uses one validation sample rather than cross-validation:

We do not use cross-validation to maintain the temporal ordering of the data. (footnote 32)

With a single validation sample, each tuning parameter combination needs only one fit, which keeps the computational effort manageable. The price is that the prediction error in the validation sample is a single, noisy estimate.

We now prepare the samples for the first out-of-sample year, 1987. For a full replication, repeat this and the following steps for every row of estimation_periods.

Random forest

Table A.5 (Internet Appendix) describes the set of hyperparameters and their potential values used for tuning each machine learning model.

For the random forest, Table A.5 fixes the number of trees at 300 and tunes the number of covariates considered at each split over \(\{3, 5, 10, 20, 30, 50, \ldots\}\); we use these six values. The paper also tunes the depth of the trees from one to six. ranger (R) and scikit-learn (Python) control the size of a tree differently: a node is only split further if it holds at least a minimum number of observations (min_n in tidymodels, min_samples_split in scikit-learn). A small minimum allows deep trees, a large one keeps them shallow; we try 5,000 and 10,000 observations.

In R, a tidymodels workflow combines the model with a recipe that tells it which columns are identifiers rather than covariates. In Python, we drop the identifier columns before we hand the data to the model as a numeric matrix. Both use all CPU cores to grow the trees.

  • R
  • Python
rf_model <- rand_forest(
  mtry = tune(),
  trees = 300,
  min_n = tune()
) |>
  set_engine("ranger", num.threads = parallel::detectCores()) |>
  set_mode("regression")

rf_grid <- expand_grid(
  mtry = c(3, 5, 10, 20, 30, 50),
  min_n = c(5000, 10000)
)

rec_model <- recipe(ret_excess ~ ., data = training |> slice_head(n = 1)) |>
  update_role(permno, date, mktcap_lag, new_role = "id")

ml_workflow <- workflow() |>
  add_recipe(rec_model) |>
  add_model(rf_model)
rf_model = RandomForestRegressor(n_estimators=300, n_jobs=-1, random_state=42)

rf_grid = {
    "max_features": [3, 5, 10, 20, 30, 50],
    "min_samples_split": [5000, 10000],
}

id_cols = ["permno", "date", "mktcap_lag"]

To tune the model, we fit it on the training sample for each combination in the grid and compare the prediction errors in the validation sample. Then we fit the best combination once more on training and validation sample together. In R, make_splits() and manual_rset() define the validation sample, tune_grid() evaluates the grid, and finalize_workflow() plus fit() produce the final model. In Python, PredefinedSplit marks which rows belong to the validation sample (0) and which are always used for training (-1); GridSearchCV evaluates the grid and, with refit=True, fits the best model on all rows.

  • R
  • Python
validation_split <- manual_rset(
  list(make_splits(training, assessment = validation)),
  ids = "validation"
)

rf_tuned <- ml_workflow |>
  tune_grid(
    resamples = validation_split,
    grid = rf_grid,
    metrics = metric_set(rmse)
  )

rf_fit <- ml_workflow |>
  finalize_workflow(select_best(rf_tuned, metric = "rmse")) |>
  fit(bind_rows(training, validation))
combined = pl.concat([training, validation])
X = combined.drop(id_cols + ["ret_excess"]).to_numpy()
y = combined["ret_excess"].to_numpy()

validation_split = PredefinedSplit(
    np.concatenate([np.full(training.height, -1), np.full(validation.height, 0)])
)

rf_tuned = GridSearchCV(
    rf_model, rf_grid,
    cv=validation_split, scoring="neg_root_mean_squared_error", refit=True
)
rf_tuned.fit(X, y)

rf_fit = rf_tuned.best_estimator_

Elastic net

The same code fits the other methods of the paper; only the model specification changes. As an example, we set up the elastic net with the mixing parameter fixed at 0.5, as in the paper, and two values of the penalty. Note the names: tidymodels calls the penalty penalty and the mixing parameter mixture, scikit-learn calls them alpha and l1_ratio. glmnet standardizes the covariates internally; in scikit-learn, we add this step with StandardScaler().

For OLS, ENet, GLM, and GBRT, we present their robust versions using Huber loss, which perform better than the version without. (p. 2250)

For simplicity, we stick to the usual squared loss. Neither glmnet nor scikit-learn’s ElasticNet offers the Huber loss; in R, the package hqreg does, but it is not a tidymodels engine.

  • R
  • Python
elastic_net <- linear_reg(penalty = tune(), mixture = 0.5) |>
  set_engine("glmnet")

enet_tuned <- ml_workflow |>
  update_model(elastic_net) |>
  tune_grid(
    resamples = validation_split,
    grid = tibble(penalty = c(1e-4, 1e-1)),
    metrics = metric_set(rmse)
  )
elastic_net = make_pipeline(StandardScaler(), ElasticNet(l1_ratio=0.5))

enet_tuned = GridSearchCV(
    elastic_net, {"elasticnet__alpha": [1e-4, 1e-1]},
    cv=validation_split, scoring="neg_root_mean_squared_error", refit=True
)
enet_tuned.fit(X, y)

The paper’s neural networks follow the same pattern; the exercise on neural networks shows how to set them up.

Machine-learning portfolios

At the end of each month, we calculate 1-month-ahead out-of-sample stock return predictions for each method. We then sort stocks into deciles based on each model’s forecasts. We reconstitute portfolios each month using value weights. Finally, we construct a zero-net-investment portfolio that buys the highest expected return stocks (decile 10) and sells the lowest (decile 1). (p. 2264)

We predict the excess returns of every out-of-sample year with the stored model.

  • R
  • Python
rf_fit <- read_rds("data-r/rf_fit_1987.rds")

predict_year <- function(oos_year) {
  out_of_sample <- read_years(oos_year, oos_year)
  out_of_sample |>
    select(permno, date, mktcap_lag, ret_excess) |>
    bind_cols(predict(rf_fit, out_of_sample))
}

For simplicity, the code above predicts all out-of-sample years with the model fitted for 1987. The paper refits the model every year. If you fit and store a model for every row of estimation_periods, read the model of the respective year inside predict_year() instead.

Every month, we sort the stocks into ten portfolios by their predicted return and compute the value-weighted predicted and realized excess return of each portfolio. assign_portfolio() from the tidyfinance package assigns the deciles in both languages, as in the Tidy Finance chapter on univariate portfolio sorts; pick(everything()) in R and map_groups() in Python hand it the stocks of one month at a time.

  • R
  • Python
ml_portfolios <- oos_predictions |>
  group_by(date) |>
  mutate(portfolio = assign_portfolio(
    data = pick(everything()),
    sorting_variable = ".pred",
    breakpoint_options = breakpoint_options(n_portfolios = 10)
  )) |>
  group_by(portfolio, date) |>
  summarize(
    ret_predicted = weighted.mean(.pred, mktcap_lag),
    ret_excess = weighted.mean(ret_excess, mktcap_lag),
    .groups = "drop"
  )
def value_weighted(col):
    return (pl.col(col) * pl.col("mktcap_lag")).sum() / pl.col("mktcap_lag").sum()


ml_portfolios = (oos_predictions
    .group_by("date")
    .map_groups(lambda month: month.with_columns(
        portfolio=tf.assign_portfolio(
            data=month,
            sorting_variable=".pred",
            breakpoint_options=tf.breakpoint_options(n_portfolios=10),
        )
    ))
    .group_by("portfolio", "date")
    .agg(
        ret_predicted=value_weighted(".pred"),
        ret_excess=value_weighted("ret_excess"),
    )
)

Finally, we add the long-short portfolio and evaluate all of them: the average predicted return, the average realized excess return, its standard deviation, and the monthly Sharpe ratio.
